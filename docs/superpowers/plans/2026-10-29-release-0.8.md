# Release 0.8.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.8.0: the 0.7.1 fixes and security work, plus the 0.8 features and website pages.

**Architecture:** This work extends the existing modules (app → feature/* → core/*). Shared network transport (SSH/FTP factories) goes in `core/data`. New tools go in `feature/tools`, the queue in `feature/upload`, the widget and shortcuts in `app`. Settings use DataStore. There are no Room schema changes.

**Tech Stack:** Kotlin 1.9.22, Compose (BOM 2024.02.00), Hilt + KSP, WorkManager, DataStore, OkHttp, Coil, Media3, Glance (new), commons-net, JSch, Play Services ML Kit text recognition.

**Spec:** `docs/superpowers/specs/2026-10-29-release-0.8-design.md` (read the section named in each task).

## Global Constraints

- No Room schema change, version stays 5. New persisted state goes in DataStore (`SettingsDataStore`/`SettingsRepository`), small files in `filesDir`/`cacheDir`, or WorkManager data.
- Secrets only in `SecureCredentialStore`. Pinned SFTP host-key fingerprints are not secrets and go in DataStore.
- compileSdk and targetSdk 35, minSdk 26. Kotlin 1.9.22. Use KSP, not kapt.
- Dependency direction stays app → feature → core. Features never depend on each other.
- UI uses the Lumen components in `core/ui/lumen`, with one accent `PillCta` per screen. Destructive actions are `OutlinedButton(CircleShape)` in error colours.
- User-facing copy is plain and human: no em or en dashes, no curly quotes.
- Commits are plain one-liners with no attribution trailers. `grep -rlP '\x{FEFF}' --include='*.kt' .` must print nothing before each commit. KDoc must not contain `image/*`.
- Build env: `export JAVA_HOME=/usr/lib/jvm/java-21-openjdk ANDROID_HOME=$HOME/Android/sdk`. Each task ends with `./gradlew testDebugUnitTest assembleDebug` green.

## Review Focus

1. A shared `content://` URI whose read permission ends after the share intent. The app must copy the file immediately on intake and never read the URI later (Task 8 test: intake copies synchronously before navigation).
2. Very large images, such as 100 MP photos, in the editor, the beautifier, the combiner and the upload worker. Each must sample or cap instead of crashing (Tasks 8, 17 and 18 test the sampling and cap maths).
3. Network loss in the middle of a batch. A retry must neither re-upload nor flag finished files as duplicates (Task 7 test).
4. An SFTP server that was legitimately re-keyed. The user gets a clear message and can recover with "Forget saved host key" (Task 5 test: forget then reconnect pins the new key).
5. Rotating the device in the editor or on the upload screen. Annotations, picked files and upload progress must survive (Tasks 3 and 16, emulator check after the size/rotation change).

### Task 5: Safe SFTP and FTPS connections

**Spec:** 1.4, SFTP and FTPS bullets.

**Files:**

- Test: `core/data/src/test/.../transfer/HostKeyStoreTest.kt`, `SshSessionFactoryTest.kt`.

**Interfaces (produces):**
- `interface HostKeyStore { suspend fun get(hostPort: String): String?; suspend fun put(hostPort: String, fingerprint: String); suspend fun remove(hostPort: String) }`. The fingerprint is `SHA256:<base64>`, as JSch's `HostKey.getFingerPrint` gives it with SHA-256.
- `class SshSessionFactory @Inject constructor(store: HostKeyStore) { suspend fun open(host: String, port: Int, user: String, password: String?, privateKey: ByteArray?, passphrase: String?, timeoutMs: Int = 15000): Session }`. It throws `HostKeyChangedException(hostPort, expected, actual)` on mismatch and pins the key on first use.
- `class FtpClientFactory @Inject constructor() { fun connect(host: String, port: Int, user: String, password: String, ftps: Boolean, passive: Boolean): FTPClient }`. With FTPS it uses `FTPSClient(false)` with hostname verification on, `execPBSZ(0)` and `execPROT("P")` after login.

- [ ] Tests:
  - `firstConnectPinsFingerprint`;
  - `matchingFingerprintConnects`;
  - `mismatchThrowsHostKeyChanged`: `expected`/`actual` are populated;
  - `forgetThenReconnectPinsNewKey`.

  Test the host key repository logic through a fake JSch `HostKeyRepository` adapter; no network.
- [ ] Implement. JSch must not get `StrictHostKeyChecking=no` anywhere; grep for it, expecting 0 hits. Replace all three SSH call sites and all FTP call sites with the factories.
- [ ] SFTP settings: a "Forget saved host key" row that calls `HostKeyStore.remove`. When the connection test or an upload hits `HostKeyChangedException`, show "The server's identity changed. Expected <expected>, got <actual>. If you changed the server's key, forget the saved key and try again."
- [ ] Commit "Verify SFTP host keys and encrypt FTPS data".
