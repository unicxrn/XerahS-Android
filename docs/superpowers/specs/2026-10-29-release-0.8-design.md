# Release 0.8.0

0.8.0 combines the planned 0.7.1 fix release with the 0.8 feature release. The work is done in three phases on `feature/0.8`. Fixes come first, so the security work is in before the feature work starts moving code around.

Source reviews (2026-10-29): upstream gap analysis against KovaForge/XerahS, a code health audit, and a product and platform review.

Out of scope: screen recording, per-profile settings (needs a Room migration), translations, the full toolchain upgrade (Kotlin 2, AGP 9), an F-Droid flavor, `.sxcu` `{select:}` and `{outputbox}`.

Constraint: no Room schema change. Anything new is stored in DataStore, small files, or WorkManager data.

## Phase 1: fixes, security and release

### 1.1 Signing and release CI
- Keep the current certificate, so 0.8.0 installs over 0.7.0. Copy the keystore to `~/.config/xerahs/release.keystore` with new, non-default store and key passwords; changing passwords does not change the certificate. Keep a backup copy next to it.
- Gradle reads signing from `keystore.properties` (gitignored) or from the env vars `XERAHS_KEYSTORE`, `XERAHS_STORE_PASSWORD`, `XERAHS_KEY_ALIAS` and `XERAHS_KEY_PASSWORD`. If neither is present, the release build is unsigned and the build says so. It never falls back to the debug keystore.
- GitHub secrets: the base64 keystore and the three passwords and alias.
- `.github/workflows/ci.yml`: runs `testDebugUnitTest lint assembleDebug` on pushes and PRs.
- `.github/workflows/release.yml`: on a `v*` tag it builds the signed release APK, checks that the signing certificate SHA-256 matches the pinned fingerprint, and attaches `XerahS-<version>.apk` to the GitHub release, creating the release as a draft if it doesn't exist.

### 1.2 Platform
- AGP 8.7.x, Gradle 8.9+, compileSdk and targetSdk 35. Kotlin stays at 1.9.22.
- Allow rotation by removing `screenOrientation="portrait"`. The editor and upload screens must work in landscape.
- Predictive back: `enableOnBackInvokedCallback="true"`.
- Uploads run as a `dataSync` foreground service, which has a 6 hour daily limit on targetSdk 35. That's not a practical issue for uploads, but handle the timeout by failing gracefully.

### 1.3 Size
- OCR moves from the bundled ML Kit model to `play-services-mlkit-text-recognition`; Google Play Services downloads the model. If Play Services is missing, OCR shows "Text recognition isn't available on this device".
- Turn on `isShrinkResources` for release.
- Target: the release APK under 15 MB.

### 1.4 Security
- **SFTP**: one shared `SshSessionFactory` is used by the uploader, the remote deleter and the connection test. It checks host keys trust-on-first-use. The fingerprint is stored per `host:port` on first connect. A mismatch fails with "The server's identity changed" and shows both fingerprints. The SFTP settings get a "Forget saved host key" action.
- **FTPS**: after login, call `execPBSZ(0)` and `execPROT("P")`, and verify the hostname. Uploader, remote deleter and connection test share one `FtpClientFactory`.
- **Backups**: add `data_extraction_rules.xml` (API 31+) and `backup_rules.xml`. Exclude the encrypted credential prefs, `files/captures`, `files/thumbnails`, `files/demo` and caches. Room and DataStore are included.
- **Share intake**: reject `file://` URIs and URIs from our own FileProvider authority. Show "Couldn't read that file".
- **Biometric lock**: allow the device PIN as a fallback (`BIOMETRIC_STRONG or DEVICE_CREDENTIAL`). With nothing enrolled, the app no longer unlocks for free; it shows "Set up a screen lock to use App lock" with a button to open settings. Use the `BiometricLockMode` enum instead of raw strings, and set `FLAG_SECURE` while locked.
- **Permissions**: `READ_MEDIA_IMAGES` stays declared but is only requested when screenshot auto-upload is turned on (2.3). Add `READ_EXTERNAL_STORAGE` with `maxSdkVersion=32` for the same feature on older versions.

### 1.5 Upload pipeline fixes
- **Batch retry**: the worker records the files it has finished in `cacheDir/upload-progress/<workId>`. A retry skips those files and doesn't treat them as duplicates. The record is deleted when the work finishes.
- **Errors**: HTTP 4xx (except 408 and 429), auth failures and "file not found" are permanent and are not retried. Network errors and 5xx retry with backoff, up to 3 attempts.
- **Notifications**:
  - each work gets its own notification ID;
  - tapping one opens the item's share screen, or the queue for failures and batches;
  - failures have a Retry action;
  - "Upload failed" is only posted on the final attempt.
- **Images**: the editor decodes off the main thread with sampling to at most 4096 px on the long edge. `UploadWorker.prepareFile` samples the same way. EXIF stripping failures fail the upload instead of silently uploading with GPS data.
- **Picker**: picked files keep their real extension and MIME type, and the input stream is always closed.
- **Cancellation**: uploads are enqueued with tag `upload` and a unique name, so they can be cancelled (2.1).

### 1.6 Navigation and UX fixes
- Home header gets a History button that opens the full History screen: albums, tags, filters, bulk delete.
- The Share screen shows "This upload no longer exists" with a back button when the item is missing.
- Onboarding lists all destinations. After "Get started" it opens the setup screen for the chosen destination. Imgur and Local need no setup.
- Home shows a "Finish setting up <destination>" banner when the default destination has no valid config.
- The capture picker accepts images and videos (`PickVisualMedia.ImageAndVideo`). A "Pick a file" option opens the document picker for any file type.

## Phase 2: features

### 2.1 Upload queue
- New Queue screen, reachable from Home and from notifications. It lists `WorkInfo`s tagged `upload`: running with progress, enqueued, failed with the reason, and finished in the last 24 hours.
- Actions: cancel running or enqueued uploads, retry failed ones (from the input stored in the failure's output data), clear finished.

### 2.2 Home-screen widget (Glance)
- 4x1 and 4x2 sizes. Shows the latest upload's thumbnail and link. Tapping the link copies it through `CopyUrlReceiver` with a toast; the Upload button opens the picker.
- Refreshes when an upload finishes.

### 2.3 Screenshot auto-upload (opt-in)
- Toggle in Upload settings, off by default. Turning it on requests the media permission.
- A worker with a MediaStore content-URI trigger watches for new images in `Screenshots/` (relative path match, API 29+; bucket name below that).
- For each new screenshot it posts "New screenshot" with the thumbnail and two actions:
  - "Upload": uploads with the default profile;
  - "Edit": opens the editor.
- A second setting, "Upload without asking", uploads straight away.

### 2.4 Sharing text, links and the clipboard
- Shared text that is a single URL opens a sheet with three options:
  - Shorten it;
  - Download and upload the file it points to (2.6);
  - Upload as text.
- Other shared text uploads as a text file through the text route (2.7).
- Home gets an "Upload clipboard" action: images in the clipboard upload as images, text as a text file, and a single URL opens the same sheet.

### 2.5 Shortcuts and direct share
- Static shortcuts: "New upload", "Upload clipboard", "Copy last link".
- One dynamic sharing shortcut per upload profile, up to 4. Sharing to one uploads to that profile without asking.

### 2.6 Upload from a URL
- Downloads the file at an http(s) URL to cache, with a 200 MB limit, a progress bar and cancel. The file name comes from Content-Disposition or the URL, the extension from Content-Type. Then it continues into the normal upload flow.
- Reachable from the URL sheet (2.4) and from an "Upload from link" option in the Upload tile's menu.

### 2.7 Routing by file type
- Upload settings get "Images go to", "Text goes to" and "Other files go to". Each one picks a profile or "Default". Stored in DataStore.
- The upload screen preselects the routed destination; the user can still change it.

### 2.8 Link formats
- New setting "Copy link as": Plain URL, Markdown, Markdown image, HTML, HTML image, BBCode, BBCode image. Image variants only apply to images and fall back to the link form for other files.
- Automatic copy after upload uses the chosen format. The share card's copy button gets a long-press menu with every format.

### 2.9 Editor: rotate and flip
- Crop mode gets rotate left, rotate right, flip horizontal and flip vertical.
- Rotating or flipping first draws the current annotations into the image, as crop already does, so nothing is lost or misplaced.

### 2.10 Beautifier tool
- New tool. Pick an image, then adjust:
  - padding;
  - background: six gradient presets, a solid color, the accent color, or transparent;
  - corner radius;
  - shadow;
  - aspect: auto, 1:1, 4:5, 16:9.
- Live preview. Actions: Upload, Share, Save to gallery.
- The editor gets a "Beautify" button that sends the current image to the tool.

### 2.11 Image combiner tool
- New tool. Pick 2 to 20 images. Options: vertical or horizontal, spacing, background color, alignment (start, center, end), and match widths or heights.
- Output preview, then Upload, Share, Save.
- The output size is capped at 8000 px on the long edge, scaling down if needed.

## Phase 3: website and docs
- `site/privacy.html`: what the app stores and where, that there's no analytics or tracking, that files go only to the destinations the user sets up, that OCR runs on device through Google Play Services, and how to contact the developer.
- `site/guides.html`: setup steps for Imgur, S3 and R2, MinIO, Nextcloud (app passwords), Immich (API key), GitHub Gist (token scope), FTP/FTPS and SFTP (host keys), and custom `.sxcu` uploaders, plus the `.sxcu` syntax we support and what we don't.
- `site/faq.html`: installing an APK, notifications, battery optimisation, duplicates, host key warnings, OCR availability.
- The footer and nav link to the new pages. They use the same styles and the same humanized copy rules.
- README: the new features, and links to the guides and privacy page.
